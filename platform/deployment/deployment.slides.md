# Do you need a deployment?

- Recorded outputs can be scored directly
- Fresh generation needs an attributable target
- Simulation needs safe repeated invocation
- Traces need emitted operational evidence

# Choose the generation

- Current Projects versioned agents/Responses
- Standalone Agents threads/runs are separate
- Record tested package set
- Status is capability-specific

# Choose the target

- Prompt configuration
- Hosted runtime/configuration
- Supported harness and features
- Actual model/tool dependencies

# Isolate evaluation

- Separate target or supported version selector
- Synthetic customers and sandbox services
- No mixed-canary provenance assumptions
- No production-routing toggles for synthetic tests

# Verify before judging

- Health and invocation
- Observed runtime version
- Tool contracts and effects
- Authorization and traces

# Optimization adds requirements

- Hosted optimizer-ready configuration
- Review local candidate and redeploy
- Prompt tool-description changes are not execution tests
- Bound repeated side effects

# Avoid absolute platform promises

- No universal cold-start latency
- No assumed zero idle cost
- Durability requires explicit design
- Model/connector counts change
